# Video to Feishu Guide

> 把软件操作录屏，整理成普通员工也能顺利照着完成的飞书图文指南。

`video-to-feishu-guide` 是一个面向 Codex 的可复用 Skill。它把录屏当作“操作证据”，而不是逐帧转写的脚本：先找出真正影响任务完成的关键画面，再按用户目标合并步骤、遮挡敏感信息、标注点击位置，最终发布并校验一份低门槛的飞书在线文档。

它解决的不是“怎样从视频中多截几张图”，而是“怎样让第一次接触这个软件的人，读完文档就能完成任务”。

## 为什么需要它

直接让 AI 根据录屏写教程，常见结果是：每次点击都变成一步、截图很多但没有重点、登录过程被拆得很碎、同一结果被反复解释，甚至把手机号、验证码和组织信息原样放进文档。

这个 Skill 把编辑判断和确定性工具结合起来：

| 常见做法 | 本 Skill 的处理方式 |
|---|---|
| 按时间顺序复述每一次点击 | 按读者要完成的目标组织步骤 |
| 手机号、验证码、登录分别写成三步 | 将熟悉的常规微操作合并成一个目标级步骤 |
| 每一步都写“完成后应该看到什么” | 下一步已能证明结果时不再重复说明 |
| 等间隔截图，画面多但价值低 | 优先选择状态变化、关键选择和成功结果 |
| 只靠提示词约束格式 | 用脚本检查编号、按钮格式、占位文本和重复表达 |
| 截图后直接上传 | 先在本地脱敏，再允许图片进入在线文档 |

## 最终会得到什么

- 一份结构完整的飞书在线图文指南，而不是录屏摘要或逐字稿。
- 围绕用户目标编排的主流程，熟悉动作被合并，风险动作被展开。
- 经过筛选、裁剪、脱敏和必要标注的关键截图。
- 统一的界面文案规范：按钮写成 **【按钮名称】**，页面状态写成“加入成功”。
- 一个明确的最终完成标准，以及只保留必要问题的故障排查部分。
- 一次发布后校验，检查结构、图文顺序、敏感信息和编辑规范。

> 当前仓库不附带真实业务录屏或账号截图。公开示例不应以泄露手机号、邮箱、验证码、邀请码、组织名称或内部页面为代价。

## 工作原理

```mermaid
flowchart LR
    A[软件操作录屏] --> B[提取候选关键帧]
    B --> C[按用户目标重组步骤]
    C --> D[本地脱敏与点击标注]
    D --> E[发布飞书在线文档]
    E --> F[结构、编辑与隐私校验]
```

这不是一个单纯的视频抽帧脚本。Skill 由三层组成：

1. **编辑层**：判断哪些操作应该合并、哪些决策必须展开，以及哪里需要显式确认成功。
2. **视觉层**：从录屏中生成候选画面和联系表，对最终截图进行遮挡与轻量标注。
3. **交付层**：将图文发布到飞书，并对文档 XML 和最终页面进行验证。

## 核心设计原则

### 录屏是证据，不是目录

鼠标移动、加载等待、重复确认和常规输入会留在视频里，但不一定应该出现在教程结构中。文档只保留帮助读者完成目标的信息。

### 按目标拆步骤，不按点击次数拆步骤

“输入账号—获取验证码—输入验证码—登录”对大多数读者来说是一个完整目标，可以写成一步；选择组织、确认发布或不可逆提交等高风险决策则应单独展开。

### 下一步已证明结果，就不重复解释

每一步都附加“完成后应该看到什么”会拉长篇幅。只有最终成功、无明显反馈的状态变化、账号或组织选择、不可逆操作等关键边界才保留结果确认。

### 先脱敏，再上传

手机号、邮箱、验证码、邀请链接、API Key、Token、内部机密和无关个人信息必须在本地遮挡。短文本和高对比度机密信息优先使用不透明色块，而不是模糊处理。

### 让机器检查确定性规则

步骤编号是否连续、图片编号是否连续、按钮是否使用统一格式、是否遗留占位文本，不需要依赖“看起来差不多”，可以交给验证脚本检查。

## 快速开始

### 1. 准备环境

- Codex Desktop 或支持 Codex Skills 的环境。
- Python 3.10 或更高版本。
- 用于抽帧和图像处理的 `opencv-python`。
- 如需直接发布飞书在线文档：已安装并完成用户授权的 `lark-cli`，以及可用的 `lark-doc` 能力。

### 2. 安装 Skill

将仓库克隆到 Codex Skills 目录。

Windows PowerShell：

```powershell
git clone "https://github.com/nanguogu/video-to-feishu-guide.git" "$env:USERPROFILE\.codex\skills\video-to-feishu-guide"
python -m pip install -r "$env:USERPROFILE\.codex\skills\video-to-feishu-guide\requirements.txt"
```

macOS / Linux：

```bash
git clone "https://github.com/nanguogu/video-to-feishu-guide.git" "$HOME/.codex/skills/video-to-feishu-guide"
python3 -m pip install -r "$HOME/.codex/skills/video-to-feishu-guide/requirements.txt"
```

安装完成后，重新打开相关 Codex 会话，使 Skill 被重新发现。

### 3. 上传录屏并发起任务

推荐直接说明录屏路径、目标读者、交付形式，以及任何必须保留或隐藏的信息：

```text
使用 $video-to-feishu-guide，把这段软件操作录屏制作成飞书在线图文指南。
文档面向第一次接触该功能的普通员工，请按用户目标合并常规操作，
保留关键选择和最终成功状态，并遮挡所有账号、验证码和组织敏感信息。

录屏：D:\recordings\employee-activation.mp4
```

如果上下文已经明确，也可以简化为：

```text
把我上传的操作录屏整理成一份面向新员工的飞书图文指南。
```

### 4. 检查交付结果

完成后应获得飞书文档链接，以及一段简短说明，包含步骤压缩、隐私处理和验证结果。建议在发布前后各做一次人工检查，尤其关注截图是否仍包含敏感信息。

## 能力一览

| 能力 | 说明 |
|---|---|
| 关键帧候选 | 周期抽帧与画面变化检测结合，生成时间标记和联系表 |
| 目标级编辑 | 合并熟悉的微操作，展开风险或容易选错的决策 |
| 截图脱敏 | 支持不透明遮挡或模糊，并可同时标记点击目标 |
| 飞书发布 | 创建在线文档、插入截图并保持图文顺序 |
| 文档校验 | 检查编号、按钮格式、占位文本、重复结果说明等规则 |
| 隐私边界 | 未经用户授权，不上传原始视频或未脱敏画面 |

## 内置工具

Skill 自带三个小型脚本。通常由 Agent 调用；需要调试或复用局部能力时，也可以单独运行。

### 提取候选关键帧

```bash
python scripts/extract_keyframes.py recording.mp4 \
  --output-dir work/frames \
  --interval 2.0 \
  --max-frames 36
```

输出包括候选帧、视频元数据和一张 `contact_sheet.jpg` 联系表。候选帧只是供选择的证据，不应未经人工或 Agent 检查就全部放进文档。

### 脱敏并标注截图

坐标格式为 `x1,y1,x2,y2`；标注可以额外附带一个编号或短标签。

```bash
python scripts/annotate_screenshot.py input.png output.png \
  --redact "120,80,460,140" \
  --mark "680,520,850,575,1"
```

同一个命令可重复传入 `--redact` 和 `--mark`。敏感字段默认使用不透明色块遮挡。

### 校验飞书文档 XML

```bash
python scripts/validate_guide.py guide.xml \
  --button "登录后加入组织" \
  --button "确认加入"
```

验证器会返回结构化 JSON 结果。它用于发现确定性问题，不能替代对截图内容、文档节奏和真实操作正确性的人工复核。

## 质量门禁

一份指南只有同时满足以下条件才算完成：

- 标题只出现一次，步骤和图片编号连续。
- 每张截图紧跟在它所解释的操作之后。
- 熟悉的微操作没有被机械拆分。
- 下一步已经证明结果时，没有重复的“完成后应该看到什么”。
- 可点击的界面标签统一写成 **【按钮名称】**。
- “加入成功”等页面状态使用引号，不与按钮混淆。
- 最终成功状态仍然清晰可判断。
- 没有占位文本、原始账号数据、邀请码、验证码、Token 或无关个人信息。
- 文档没有补写录屏中未出现、也未经确认的操作。

## 适用场景

- 新员工入职、企业账号激活和组织加入指南。
- 软件安装、配置、登录和首次使用教程。
- 后台操作 SOP、内部系统培训和客户支持文档。
- 需要从真实演示中提取步骤，但又不能公开原始录屏的场景。
- 团队希望复用统一的图文教程编辑规范和验收门禁。

## 不适用场景

- 对访谈、课程、会议或宣传视频做摘要、字幕或逐字稿。
- 完全自动理解录屏之外的业务规则，并补写未演示的操作。
- 在无人复核的情况下处理包含高敏感数据或高风险操作的流程。
- 取代产品官方说明、合规审核、权限审批或安全评审。
- 仅依赖脚本一键生成最终教程；关键步骤选择和编辑判断仍由 Agent 完成。

## 隐私与安全

原始录屏和未脱敏画面默认只在本地工作目录处理，不应进入 Git、飞书或其他外部服务。公开仓库已忽略常见视频、候选帧和临时工作目录，但这不是隐私检查的替代品。

建议遵循以下边界：

- 原视频始终保留，不在原文件上覆盖处理。
- 任何图片离开本机前，按原始尺寸逐张检查。
- 验证码、密钥、Token 和短邀请码使用实色遮挡。
- 只上传最终选中的脱敏截图，不上传整段录屏或候选帧目录。
- 飞书文档默认使用请求者的用户身份创建，避免生成其无法访问的机器人所有文档。

## 常见问题

<details>
<summary><strong>它能全自动把任何录屏变成教程吗？</strong></summary>

不能保证。脚本能稳定完成候选抽帧、标注和规则校验，但“哪些操作值得保留”“读者是否需要额外解释”仍依赖录屏质量、目标受众和 Agent 的编辑判断。对高风险流程应保留人工验收。
</details>

<details>
<summary><strong>为什么不把录屏里的每次点击都写下来？</strong></summary>

教程的目标是让读者完成任务，不是复刻操作者的鼠标轨迹。常规输入和登录动作拆得过细，会增加篇幅和认知负担；只有容易出错、不可逆或反馈不明显的动作需要展开。
</details>

<details>
<summary><strong>必须输出到飞书吗？</strong></summary>

当前 Skill 的发布与校验规范针对飞书在线文档。编辑原则和图像脚本可以复用到其他载体，但直接发布到其他平台不在当前能力范围内。
</details>

<details>
<summary><strong>可以把真实录屏提交到 Issue 吗？</strong></summary>

不建议。请先移除账号、组织、客户、验证码、邀请链接和内部系统信息；能用合成数据复现时，不要上传真实业务素材。
</details>

<details>
<summary><strong>产品界面更新后怎么办？</strong></summary>

重新使用最新录屏生成或局部更新指南，并在文档中保留适当的更新时间说明。不要仅凭旧版产品经验补写新界面步骤。
</details>

## 可探索方向

以下是适合社区继续验证的方向，不代表已经实现或承诺交付：

- 提供完全脱敏的合成演示录屏和前后对比样例。
- 用 OCR 辅助提示可能包含账号、验证码和 Token 的区域。
- 增加更多在线文档目标，同时保留相同的编辑质量门禁。
- 为飞书文档增加更完整的视觉回归与链接有效性检查。
